빠진 기능 체크리스트

목업 화면을 눌러보면서 기획서/이슈에 명확히 정의돼 있지 않던 지점들을 찾고, 2026-11-03에 팀 논의를 거쳐 대부분 이슈로 반영했습니다. 아래는 그 처리 결과입니다.

✅ 이슈로 반영 완료 (2026-11-03)

로그아웃 / 회원정보 수정 / 회원탈퇴 API 없음 — User/로그인 쪽은 #5·#15만 있고 로그인 "이후" 계정 관리 API가 없었음. → #32로 추가 완료 (담당 A). refreshToken 컬럼 추가, 탈퇴는 소프트 삭제(status=WITHDRAWN).
(참고: 회원가입은 카카오 최초 로그인=자동가입이라 별도 이슈 없음 — 의도된 설계)
교환 중개 가게를 누가/언제 정하는가 — "가게가 중개한다"고만 있고 배정 시점/방법이 없었음. → #10 수정: ExchangeItem에 shopId 추가, 게시글 작성 시 글쓴이가 직접 배정. 이름검색 UI를 위해 #6에 GET /api/shops?name= 파라미터도 같이 추가. exchange.html에 이름검색 선택 UI 반영 완료.
경매 보증금 비율/금액 미정 — "최초 입찰 시 보증금 1회 예치"만 있고 금액 기준이 없었음. → #12 수정: Auction.depositAmount 추가, 경매 개설 시 가게가 직접 금액을 정함 (단, startPrice의 10%~20% 범위로 제한). #20도 이 필드를 참조하도록 같이 수정. auction.html 개설 폼에 보증금 입력란 + 범위 검증 반영 완료.
교환 게시글 댓글 — 게시판처럼 ExchangeItem에도 질문/답변을 남길 수 있으면 좋겠다는 피드백. → #33 신규 이슈(ExchangeComment, 담당 C). 새 테이블 1개 추가됨 — Tier1 18개 ERD에서 19개로 늘어남. exchange.html에 댓글 UI 반영 완료.
가게 구독 상태 "목록" 조회 API 없음 — 8절엔 관리자가 구독 현황을 관리한다는데 목록 GET이 명세에 없었음. → #16 수정: GET /api/admin/subscriptions 추가. admin.html에 "가게 구독 현황 목록" 섹션 반영 완료.
유저 전체 결제내역 조회 API 없음 — 도메인별 "내 ~ 목록"만 있고 Payment 자체를 모아보는 API가 없었음. → #9 수정: GET /api/payments/me 추가. payment.html은 이미 이 형태로 동작 중(이번에 공식 API로 확정).
알림 기능 전혀 없음 — 교환 수락/거절, 이벤트 취소, 경매 낙찰 등 상태 변화를 유저가 알 방법이 없었음. → #34 신규 이슈(Notification, 담당 A 제안). Tier1로 결정 (가벼운 인앱 알림만 — 푸시/이메일/실시간 제외). 새 테이블 1개 추가. notifications.html + 교환/이벤트/경매/환불/입점승인 각 화면에 알림 발생 지점 반영 완료.
검색/필터 UI 반영 필요 — Item/Shop API엔 쿼리파라미터가 이미 있는데 화면에 필터 UI가 없었음. → 백엔드 API는 이미 충분(#6/#7). #24(화면 전환 체크리스트)에 "카테고리/지역 필터 UI 필요" 체크항목 추가. items.html에 카테고리 필터 드롭다운 반영 완료.
상품 이미지 필드 없음 — 포토카드/굿즈 특성상 사진이 거의 필수인데 Item에 필드가 없었음. → #7 수정: Item.imageUrl(nullable String) 추가. 실제 파일 업로드(S3)는 그대로 Tier2 유지, Tier1은 URL 문자열만. items.html 등록폼/카드에 반영 완료.
이벤트/경매 마감의 유저 체감 — 스케줄러로 자동 마감되는데 화면엔 아무 신호가 없었음. → 데이터는 API에 이미 있어서 백엔드 이슈는 불필요. #24에 "마감 카운트다운 + 이벤트 남은자리 표시" 체크항목 추가. event.html/auction.html/exchange.html에 카운트다운, event.html에 "남은 자리 N명" 반영 완료.

🔵 확장 아이디어로 보류 (지금은 이슈화하지 않음)

유저간 채팅 — ChatLog는 AI 에이전트 전용이고, 교환 상대방과 직접 대화(만날 시간 조율 등)할 방법이 없음. "가게가 현장에서 확인"하는 구조라 필수는 아니라고 판단 — 2026-11-03 논의에서 지금은 안 만들고 확장 아이디어로 남겨두기로 결정. 나중에 필요해지면 Board/Reply나 ExchangeComment(#33) 패턴 재사용 가능.

🟢 이미 Tier2로 명시적으로 미뤄진 것 (참고, 문제 아님)

개인유저 경매인증, 경매 안티스나이핑(자동연장), AI 이미지 진위감정, 실시간 WebSocket 중계, 주소검색 API, 신고(Report) — 기획서 4절에 Tier2로 명시돼 있음.
