# 오라클 클라우드 무료 서버에 배포하기

심사하는 사람이 주소만 열면 바로 확인할 수 있게, 서버 한 대에 앱·DB·HTTPS를 같이 올린다. 비용은 0원이다(무료 한도 안에서 쓸 때).

```
브라우저 ──HTTPS(443)──▶ Caddy ──▶ 앱(8080) ──▶ MySQL
                    (인증서 자동)        │
                                     상품 이미지 볼륨
```

- 바깥에 열리는 포트는 **80, 443**뿐이다. MySQL과 앱 포트는 열지 않는다.
- 앱·DB·프록시는 `docker compose -f docker-compose.prod.yml` 한 번으로 같이 켜진다.
- Oracle 콘솔의 화면·메뉴 이름은 바뀔 수 있다. 아래 이름과 다르면 비슷한 항목을 찾는다.

## 0. 준비물

- 신용/체크카드 (Oracle 가입 인증용, 무료 한도 안에서는 결제되지 않는다)
- 카카오 개발자 계정과 이 앱의 카카오 로그인 설정 권한
- PortOne 콘솔 권한 (테스트 채널)
- Gemini API 키 (챗봇 용도)

## 1. 서버 만들기

1. Oracle Cloud에 가입한다. 홈 리전은 가까운 곳(서울 또는 춘천)을 고른다. 가입 후 리전은 바꿀 수 없다.
2. 컴퓨트 → 인스턴스 만들기.
   - 이미지: **Ubuntu 24.04** (또는 22.04)
   - 모양(Shape): **Ampere `VM.Standard.A1.Flex`**, OCPU 2개 / 메모리 12GB 정도. **"Always Free 사용 가능" 표시가 있는 것만** 고른다. 표시가 없으면 과금된다.
   - 1GB짜리 AMD 모양(`VM.Standard.E2.1.Micro`)은 쓰지 않는다. 앱과 MySQL이 같이 약 1.2GB를 써서 모자란다.
   - 공용 IP 주소 할당을 켠다. SSH 키는 **개인 키를 내려받아 잘 보관한다** (잃어버리면 접속할 수 없다).
3. "Out of capacity(용량 부족)" 오류가 나면 잠시 뒤 다시 시도하거나 다른 가용 도메인(AD)을 고른다. 시간대를 바꿔 여러 번 시도하면 된다.

## 2. 포트 열기 (80, 443)

두 군데를 모두 열어야 한다. 하나만 열면 접속되지 않는다.

1. **Oracle 콘솔**: 네트워킹 → 가상 클라우드 네트워크 → 서브넷의 보안 목록(Security List) → 수신 규칙 추가
   - 소스 CIDR `0.0.0.0/0`, TCP, 대상 포트 `80`, 같은 방식으로 `443`
2. **서버 안 방화벽**: Oracle의 Ubuntu 이미지는 기본으로 대부분의 포트를 막아 둔다.

```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo apt-get install -y iptables-persistent   # 재부팅 뒤에도 유지 (묻는 질문에는 Yes)
sudo netfilter-persistent save
```

## 3. 서버 접속과 Docker 설치

```bash
ssh -i <내려받은 개인키> ubuntu@<서버 공인 IP>

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # 적용하려면 로그아웃 후 다시 접속
docker compose version             # 버전이 나오면 정상
```

## 4. 코드 받고 설정 채우기

```bash
git clone https://github.com/leeyonghee030/GoodsBridge.git
cd GoodsBridge
cp deploy/prod.env.example .env
nano .env
```

`.env`에서 채울 것 (`deploy/prod.env.example`에 설명이 있다):

| 항목 | 값 |
|---|---|
| `DOMAIN` | 사이트 주소(도메인만). 도메인이 없으면 서버 공인 IP의 점을 `-`로 바꿔 `.nip.io`를 붙인다. 예) `129.154.1.2` → `129-154-1-2.nip.io` |
| `DB_PASSWORD`, `JWT_SECRET` | **서버에서 새로 만든 긴 무작위 문자열**. 개발 PC 값을 그대로 쓰지 않는다 |
| `KAKAO_REDIRECT_URI` | `https://<DOMAIN>/oauth2/kakao` |
| `GEMINI_API_KEY`, `PORTONE_*`, `KAKAO_*` | 발급받은 값 |
| `APP_DEMO_ENABLED` | 심사자가 데모 계정으로 바로 둘러보게 하려면 `true` |

무작위 문자열 만들기: `openssl rand -base64 48`

> `.env`는 서버에만 둔다. 깃에 올리지 않는다.

## 5. 카카오·PortOne 설정 (콘솔에서 직접)

- **Kakao Developers** → 내 애플리케이션 → 카카오 로그인
  - Redirect URI에 `https://<DOMAIN>/oauth2/kakao`를 **`.env`의 `KAKAO_REDIRECT_URI`와 글자까지 똑같이** 등록한다
  - 플랫폼(웹) 사이트 도메인에 `https://<DOMAIN>`을 추가한다
  - 이게 다르면 카카오 로그인이 실패한다 (`redirect_uri_mismatch`)
- **PortOne 콘솔**: 테스트 채널 키를 쓰고, 허용 도메인(있으면)에 `https://<DOMAIN>`을 추가한다

## 6. 켜기

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

- 첫 빌드는 5~10분 걸린다 (Gradle이 라이브러리를 내려받고 jar를 만든다). ARM 서버에서도 같은 명령이다.
- 앱이 뜨는 데는 20~30초 더 걸린다. 그동안 주소를 열면 502가 나올 수 있다.

```bash
docker compose -f docker-compose.prod.yml ps        # 3개가 Up 이면 정상 (mysql 은 healthy)
docker compose -f docker-compose.prod.yml logs -f app   # "Started GoodsBridgeApplication" 이 보이면 완료
```

## 7. 확인

휴대폰(와이파이 끄고 LTE)과 다른 PC에서 `https://<DOMAIN>`을 연다.

- [ ] 첫 화면이 열리고 주소창에 자물쇠(HTTPS)가 보인다
- [ ] 카카오 로그인이 된다
- [ ] 시연 모드를 켰다면 화면 위쪽 DEMO 막대로 구매자·가게·관리자 계정이 바뀐다
- [ ] 상품 이미지를 올리고 다시 열어도 보인다

## 8. 코드 업데이트하기

```bash
cd GoodsBridge
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

DB 데이터와 업로드한 이미지는 Docker 볼륨(`mysql-data`, `uploads`)에 있어서 업데이트해도 남는다.

## 9. 시연 모드로 켜 둘 때 알아둘 것

- `APP_DEMO_ENABLED=true`이면 교환 보증금 결제를 건너뛰는 시연용 동작이 켜진다. 실제 결제를 받는 서비스에서는 `false`로 둔다.
- 서버를 켤 때와 매일 새벽 4시에 시연 데이터가 새로 만들어진다. 그날 만든 시연 중 데이터는 초기화된다.
- 자세한 내용은 [데모 임시데이터 사용법](데모_임시데이터_사용법.md)을 본다.

## 10. 자주 막히는 경우

| 증상 | 원인과 해결 |
|---|---|
| 주소가 아예 안 열린다 (시간 초과) | 2절의 두 군데 방화벽 중 하나가 닫혀 있다. Oracle 수신 규칙과 서버 iptables를 다시 확인한다 |
| 502 Bad Gateway | 앱이 아직 뜨는 중이다. 30초 뒤 다시 열고, 계속되면 `logs -f app`을 본다 |
| 인증서 오류 / HTTPS가 안 된다 | `DOMAIN`이 실제 공인 IP를 가리키는지, 80·443이 열려 있는지 본다. `logs caddy`에 발급 실패 이유가 나온다. nip.io 같은 공용 도메인은 인증서 발급 횟수 제한에 걸릴 수 있다 |
| 앱이 계속 재시작된다, `Access denied for user` | DB 비밀번호는 **MySQL 볼륨을 처음 만들 때** 정해진다. `.env`의 `DB_PASSWORD`를 나중에 바꿨다면 `docker compose -f docker-compose.prod.yml down -v`로 볼륨을 지우고 다시 켠다 (데이터가 모두 지워진다) |
| 카카오 로그인이 안 된다 | 5절의 Redirect URI가 `.env`와 한 글자라도 다르다 |
| 서버가 느려지고 앱이 죽는다 | 메모리 부족이다. 1GB 모양을 썼다면 A1(Ampere)로 다시 만든다 |
| 개발 PC에서 이 compose를 시험하는데 DB 접속이 거부된다 | 그 PC의 시스템 환경 변수 `DB_PASSWORD`가 `.env`보다 우선한다. `env -u DB_PASSWORD docker compose …`처럼 빼고 실행한다. 서버에서는 해당 없음 |

## 11. 무료 서버를 오래 쓰는 팁

- Oracle은 오랫동안 거의 쓰지 않는 무료 서버를 회수할 수 있다. 주기적으로 접속해 쓰고, 중요한 데이터는 따로 백업한다.
- 백업: `docker compose -f docker-compose.prod.yml exec -T mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' > backup.sql`
- 무료 한도(Always Free 표시가 붙은 모양과 용량)를 넘기지 않는다.
