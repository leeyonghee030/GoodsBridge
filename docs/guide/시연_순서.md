# 시연 순서

발표·시연 때 15~20분 안에 핵심 기능을 보여주는 순서입니다.
**데모 계정으로 직접 누르는 "실제 사용자 화면"** 과, 손으로는 재현할 수 없는 부분을 버튼 한 번으로 보여주는 **"기능 시연" 화면**을 섞어서 진행합니다.

> 데모 계정·결제 생략·들어 있는 데이터는 [데모 임시데이터 사용법](데모_임시데이터_사용법.md)을 보세요.

## 0. 준비 (시작 전)
1. `.env`에 `APP_DEMO_ENABLED=true`를 넣고 서버를 켭니다.
2. **서버를 켜고 1분쯤 기다렸다가** 시작합니다. 켠 직후에는 데모 데이터 생성·구독 정합성 검사와 겹쳐 시연 버튼이 오류를 낼 수 있어요.
3. 오른쪽 위 **DEMO** 메뉴에서 **결제 X**인지 확인하고, **초기화**를 한 번 눌러 깨끗한 상태로 시작합니다.
4. 탭을 미리 열어 두면 편해요: 메인(`/`), 기능 시연(`/demo/concurrency`)
5. AI 챗봇을 보여줄 거면 `.env`에 `GEMINI_API_KEY`가 있는지 확인합니다.

**기능 시연 화면**: DEMO 메뉴 → **기능 시연**. 위쪽 탭으로 오갑니다.

| 탭 | 보여주는 것 |
|---|---|
| 선착순 이벤트 | 여러 명이 동시에 참가 신청할 때 락 없음/있음 비교 |
| 경매 입찰 | 같은 금액 동시 첫 입찰 때 락 없음/있음 비교 |
| 노쇼 정산 | 둘 다 옴 / 한쪽만 노쇼 / 둘 다 노쇼 보증금 정산 |
| 시간 빨리감기 | 마감 시간이 지나야 도는 스케줄러를 바로 실행 (시나리오 6개) |

## 1. 서비스 소개 (1분, 로그인 없이)
- 메인 화면에서 한 줄 소개: "오프라인 굿즈샵을 거점으로 안전하게 교환하는 중고거래 플랫폼. 수익은 유저 수수료가 아니라 **가게 구독료(B2B)**."
- 가게 목록과 교환 게시판을 넘겨 보여줍니다. (샘플 데이터가 많아 실제 서비스처럼 보여요)

## 2. 안전 교환 (4분), 핵심 기능 ①
1. **B**로 바꾸고, A의 교환 글에 내 굿즈로 제안합니다. (보증금 결제)
2. **A**로 바꾸면 알림이 와 있어요. 수락합니다. (A 보증금 결제)
3. **가게**로 바꾸고 교환 관리에서 두 사람 출석을 체크합니다.
4. 기능 시연 → **노쇼 정산**: 경우 버튼을 하나씩 눌러 보증금 정책을 보여줍니다.
   - 둘 다 옴: 각자 75% 환불, 25% 가게 / 한쪽만 노쇼: 온 사람 100% 환불, 안 온 사람 0% / 둘 다 노쇼: 각자 50% 환불
   - "보증금 = 자기 상품 가격의 20%, 최소 2,000원"도 같이 짚어 줍니다. (B 8,000원 → 20%는 1,600원이라 최소 2,000원 적용)
5. 시간 빨리감기 → **교환 · 출석 체크 유예**: "가게가 실수로 눌러도 5분 안에는 되돌릴 수 있고, 5분이 지나면 자동으로 정산된다."
6. (질문이 나오면) 시간 빨리감기 → **교환 · 제안 기한 만료**: "상대가 3일 안에 응답하지 않으면 제안이 만료되고 보증금이 자동으로 전액 환불된다."

## 3. 선착순 이벤트 (3분), 핵심 기능 ② + 동시성
1. **B**로 이벤트에 참가합니다. (번호표 발급)
2. 기능 시연 → **선착순 이벤트**: 정원 5, 20명으로 실행합니다.
   - "락이 없으면 20명이 다 성공하고 DB엔 판매 수가 2만 남아요. 실제 코드는 비관적 락(`SELECT ... FOR UPDATE`)으로 딱 5명만 성공해요."
   - 락 없음 카드 아래 설명(DB 연결이 10개라 10명씩 같은 값을 읽고 덮어씀)을 같이 읽어 주면 이해가 쉬워요.
3. 시간 빨리감기 → **선착순 이벤트**: 마감 시간이 지나면 참가비가 가게 정산에 기록되고 참가자에게 알림이 갑니다.

## 4. 경매 (4분), 핵심 기능 ③
1. **B**로 진행 중인 경매(예: 오늘 마감인 스탠딩 인형)에 입찰합니다. (첫 입찰 때 보증금)
2. 기능 시연 → **경매 입찰**: "같은 금액으로 동시에 입찰하면, 락이 없을 땐 여러 명이 '최고 입찰자' 응답을 받고 보증금도 걷히지만, 실제 코드는 1명만 성공해요."
3. 시간 빨리감기 → **경매 · 낙찰 성공**: 마감 → 낙찰·패찰 보증금 환불 → 배송지 입력·잔금 결제 → 가게 발송(송장) → 배송 완료 → 구매 확정·가게 정산까지 한 번에 보여줍니다.
4. 시간 빨리감기 → **경매 · 잔금 미납**: "잔금을 기한 안에 안 내면 낙찰이 취소되고 보증금은 가게 몫."

## 5. 가게 = 고객 (B2B 수익 모델) (3분)
1. **가게**로 바꿔 대시보드, 정산, 이벤트·경매·판매 관리 화면을 보여줍니다.
2. 시간 빨리감기 → **가게 구독 만료**: "구독이 끊기면 상품 판매가 멈추고 선착순 이벤트 참가도 막힌다. 그래서 가게가 구독을 유지한다 = 우리의 수익 모델."
3. **가게B**로 바꿔 처음 구독을 시작하는 흐름을 보여줍니다. (결제 X라 바로 돼요)

## 6. 관리자 (1분)
- **관리자**로 바꿔 대시보드, 입점 승인, 구독 관리를 보여줍니다.

## 7. AI 챗봇 (1분, `GEMINI_API_KEY`가 있을 때만)
- **B**로 "내 교환 상태 알려줘", "진행 중인 경매 알려줘"처럼 질문해 내 거래를 조회하는 걸 보여줍니다.

## 8. 마무리
- "동시성과 정산은 자동화 테스트로도 검증한다"는 말과 함께 README의 테스트 섹션이나 `./gradlew test` 결과를 짧게 보여줍니다.

## 말할 때 포인트
- 손으로 누르는 흐름은 "실제 사용자 화면", 기능 시연 탭은 "손으로는 재현할 수 없는 부분(동시 요청, 시간이 지나야 도는 스케줄러)"이라고 구분해서 말하면 듣는 사람이 헷갈리지 않아요.
- 기능 시연은 모두 **실제 서비스 코드와 실제 스케줄러**를 그대로 돌리고, 화면의 금액은 결제·정산 기록에서 읽은 값이에요. "시연용으로 따로 계산한 게 아니다"를 강조하면 좋아요. (락 없음 비교 코드만 시연 전용)
- 기능 시연은 누를 때마다 임시 데이터를 만들고 끝나면 지워서, 데모 데이터와 섞이지 않고 몇 번이든 다시 누를 수 있어요.

## 오류가 날 때
- 버튼이 "서버 내부 오류"를 내면 몇 초 뒤 다시 누릅니다. (서버를 막 켰을 때 시작 작업과 겹친 경우가 대부분)
- 화면이 이상하면 DEMO → **초기화**를 누르고 새로고침합니다.
- 새 기능이 화면에 안 보이면 서버를 새 코드로 다시 켰는지 확인하고, 브라우저에서 `Ctrl + F5`로 새로고침합니다.
