# 데모 임시데이터 사용법

로그인·결제 없이 **일반 손님 / 가게 / 관리자** 화면을 바로 확인할 수 있게 해 주는 시연 기능입니다.
기능을 확인(리뷰)할 때 이 데이터를 쓰면 가입·결제 없이 바로 테스트할 수 있어요.

## 1. 켜는 방법
1. `.env`에 아래 값을 넣습니다. (`.env.example`에 설명이 있어요. `.env`는 커밋하지 않습니다.)
   ```
   APP_DEMO_ENABLED=true
   ```
2. 서버를 (재)시작합니다. 서버가 켜질 때 **데모 데이터가 자동으로 새로 만들어져요.**
3. 화면 오른쪽 위에 `DEMO` 막대가 보이면 켜진 거예요.

> `APP_DEMO_ENABLED`가 비어 있거나 `false`이면 데모 막대, 데모 계정, 결제 생략이 **전부 꺼집니다.**

## 2. 데모 막대로 계정 바꾸기
화면의 `DEMO` 막대를 열면 버튼이 있어요. 누르면 로그인 없이 그 계정으로 바뀝니다.

| 버튼 | 계정(닉네임) | 용도 |
|---|---|---|
| **A** | 데모교환A | 교환 게시글을 올린 손님 |
| **B** | 데모신청B | 교환을 신청하고 이벤트·상품을 사는 손님 |
| **가게** | 데모가게 | 입점·구독 중인 가게 (`데모 굿즈샵`) |
| **가게B** | 데모가게B | 입점만 승인된, 구독을 처음 시작하는 가게 |
| **관리자** | 데모관리자 | 관리자 화면 (입점·구독·대시보드) |

- **초기화** 버튼: 시연하며 바뀐 데이터를 처음 상태로 되돌립니다.
- **결제 X / 결제 O** 버튼: 누를 때마다 바뀝니다. (아래 3번)
- 코드로 바꾸고 싶다면 `POST /demo/login/{user-a|user-b|shop|shop-b|admin}` 을 호출하면 돼요.

## 3. 결제는 어떻게 되나요?
- 기본은 **결제 X**: 결제창 없이 바로 통과해요. 가짜 결제도 `payment_tb`에 `demo-pay-…` 번호로 저장돼서, 환불·정산이 정상적으로 이어져요.
- **결제 O**로 바꾸면 실제 PortOne 결제창이 떠요. (실제 결제 확인용)
- 결제를 생략해 주는 종류: **상품 구매, 교환 보증금, 이벤트 참가비, 가게 구독료, 경매 보증금·낙찰 잔금**. (경매도 `결제 X`면 결제창 없이 입찰·잔금 결제가 돼요)

## 4. 어떤 데이터가 들어 있나요?
모든 날짜는 **서버가 켜진 시각(오늘) 기준**으로 만들어져요. 며칠 뒤에 켜도 똑같이 쓸 수 있어요.

- **상품(SHOP):** 카테고리마다 데모가게의 판매 상품, 구매·환불·정산 내역(이번 달/저번 달/그 전 달)
- **교환:** 교환A가 올린 교환 게시글 + 교환B의 신청(대기·취소·거절·확정·만남 확정·완료·노쇼 등 여러 상태)
- **선착순 이벤트 (총 9개)**

  | 이벤트 | 상태 | 볼 수 있는 것 |
  |---|---|---|
  | D-Series 스페셜 쿠지 (100개 한정) | 모집중 | 같은 번호표에 구매 2건(추가 구매), 교환A 참가 |
  | 한정판 포토카드 / 시즌 그리팅 | 모집중 | 참가자 없음 (참가·수정 테스트용) |
  | 만화 컷 아트 포스터 | 모집중 | 참가 1건 |
  | 스탠딩 피규어 한정판 | 모집중 | 내가 취소한 구매 1건 포함 |
  | 모집 마감 · 방문 대기 | 모집 마감, **방문 날짜가 오늘** | 가게 '오늘 방문' 탭, 오늘 정산 |
  | 지난 주 종료된 이벤트 | 종료 | 지난주 정산 |
  | 지난 달 종료된 이벤트 | 종료 | 저번 달 정산 |
  | 가게 사정으로 취소된 이벤트 | 가게 취소 | 환불된 참가 |
- **경매 (7개):** 사진은 올려 둔 피규어 풀박스/스탠딩 인형을 써요.

  | 경매 | 상태 | 볼 수 있는 것 |
  |---|---|---|
  | D-Series 한정판 피규어 풀박스 | 진행중 (D-2) | 입찰 4회, **데모교환A가 최고가** (데모신청B 화면에서는 '다른 사람이 최고가') |
  | D-Series 스탠딩 인형 한정판 | 진행중 (오늘 마감) | 입찰 4회, **데모신청B가 최고가** |
  | 사인 포토카드 세트 | 진행중 | 입찰 없음 → 가게가 취소할 수 있고, 처음 입찰(보증금) 테스트용 |
  | 한정판 아크릴 스탠드 세트 | 종료 · 낙찰 | **데모신청B가 낙찰, 잔금 결제 대기** (결제 기한 하루 뒤) |
  | 일러스트 포스터 세트 | 종료 · 낙찰 | 데모교환A가 잔금까지 결제 완료 (구매 내역·정산 기록 포함) |
  | 응원봉 키링 | 유찰 | 입찰 없음 |
  | 취소된 경매 상품 | 취소 | 가게가 취소 |
- **가게 지점:** 성수점(구독중) / 잠실점(만료 임박) / 대전점(만료됨) 등 관리자 화면 확인용

## 5. 데이터가 초기화되는 때
1. **서버를 켤 때마다** (재시작 포함)
2. **데모 막대의 `초기화` 버튼**을 누를 때
3. **매일 새벽 4시** 자동으로 (서버를 켜 둬도 날짜가 낡지 않게)
   - 시각 변경: `app.demo.daily-reset-cron` 설정 (기본 `0 0 4 * * *`)

초기화하면 **데모 계정(A, B, 가게)이 만든 상품·교환·이벤트·참가·구매 데이터는 지워지고 다시 만들어져요.**

## 6. 주의할 점 ⚠️
- **운영/배포 환경에서는 절대 켜지 마세요.** 켜져 있으면 누구나 결제 없이 교환·구매·참가를 할 수 있고, 데모 계정으로 바로 로그인할 수 있어요.
- **같은 DB를 여러 명이 같이 쓰면** 한 사람이 초기화(또는 서버 재시작)할 때 다른 사람이 보던 데모 데이터도 같이 바뀌어요. 각자 로컬 DB(docker-compose의 MySQL)를 쓰는 걸 권장해요.
- **내가 데모 계정으로 만든 데이터는 초기화 때 사라져요.** 남겨야 하는 데이터는 데모 계정이 아닌 일반 계정으로 만드세요.
- 새벽 4시 자동 초기화 시각에 **시연/테스트 중이면 데이터가 갑자기 바뀔 수 있어요.**
- **가게 계정은 구매·교환·이벤트 참가·경매 입찰을 할 수 없어요.** (가게는 파는 쪽이에요.) 손님 기능을 보려면 A 또는 B 계정으로 바꾸세요.
- 데모로 만든 가짜 결제(`demo-pay-…`)는 실제 PortOne에는 없어요. 실제 결제 흐름을 확인하려면 `결제 O`로 바꿔서 테스트하세요.
- 데모 전용 코드는 `TODO(데모 종료 후 제거)` 주석이 달려 있어요. 발표/배포 전에는 `APP_DEMO_ENABLED`를 끄거나 해당 코드를 제거합니다.

## 7. 자주 하는 확인 흐름 (예시)
- **이벤트 추가 구매:** `B` → `EVENT` → 스탠딩 피규어 → 추가 구매 / 마이페이지 → 이벤트 내역에서 구매 건 취소
- **이벤트 수정·정산:** `가게` → MY PAGE → 이벤트 관리 → `···` 메뉴(수정), `정산` 탭(달력)
- **경매:** `B` → `AUCTION` → 진행중 경매에서 입찰 / 마이페이지 → 경매 내역(낙찰 → 잔금 결제) / `가게` → 경매 관리(경매 열기·취소)
- **교환 알림 등:** `A`와 `B`를 번갈아 바꿔 가며 교환 신청 → 수락 → 알림 확인
- **관리자 대시보드:** `관리자` → 관리자 화면

문제가 생기면 먼저 `초기화` 버튼을 눌러 데이터를 처음 상태로 되돌린 뒤 다시 시도해 보세요.
