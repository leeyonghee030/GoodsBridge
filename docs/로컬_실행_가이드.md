# 로컬 실행 가이드 (Windows PowerShell)

처음 세팅하는 사람도 그대로 따라 하면 되게 정리했어요.
(README의 "빠른 시작"을 PowerShell 기준으로 풀어 쓴 것)

## 0. 준비물 (컴퓨터당 한 번)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) 설치 → **실행해 둔 상태**로 (화면 아래 고래 아이콘이 초록색)
- Java 21, Git

터미널에서 확인해요. 둘 다 버전이 나오면 준비 끝이에요.
```powershell
docker --version
docker compose version
```
> `docker 용어를 인식할 수 없다`고 나오면 → Docker Desktop을 설치/실행하고, **PowerShell을 닫았다가 다시 열어요.**

## 1. 처음 켤 때 (순서대로)
프로젝트 폴더(`GoodsBridge`)에서 PowerShell을 열고 한 줄씩 실행해요.

### ① 환경 파일 만들기
```powershell
Copy-Item .env.example .env
```
- `.env` 파일을 메모장/IDE로 열어서 `DB_PASSWORD=` 뒤에 **아무 값이나** 적어요. (예: `DB_PASSWORD=1234`)
- 이미 `.env`가 있으면 이 단계는 건너뛰어요. (덮어쓰면 기존 설정이 사라져요)
- `.env`는 **절대 커밋하지 않아요.**

### ② DB 띄우기
```powershell
docker compose up -d
docker ps
```
- `docker ps` 결과에 **`goodsbridge-mysql`** 이 보이면 성공이에요.
- 한 번 띄워 두면 계속 켜 둬도 돼요. 컴퓨터를 껐다 켰으면 Docker Desktop부터 실행하세요.

### ③ 서버 켜기
```powershell
.\gradlew.bat bootRun
```
- IntelliJ로 켜는 분은 실행 버튼을 눌러도 돼요.
- 처음 켤 때 **테이블은 서버가 알아서 만들어요.** 따로 만들 필요 없어요.
- 터미널에 `Started GoodsBridgeApplication` 이 보이면 성공이에요.

### ④ 잘 켜졌는지 확인
브라우저에서 http://localhost:8080/test/event 가 열리면 성공이에요.
데모 모드를 켰다면(`.env`에 `APP_DEMO_ENABLED=true`) 화면 오른쪽 위에 `DEMO` 막대가 보여요.

## 2. DB에 테이블이 있는지 확인하는 방법
> 서버를 **한 번도 안 켠** 새 DB라면 테이블이 없는 게 정상이에요. 서버를 켜면 생겨요.

### 2-1. DB 안으로 들어가기
```powershell
docker exec -it goodsbridge-mysql mysql -uroot -p
```
- `Enter password:` 가 나오면 `.env`의 **`DB_PASSWORD` 값**을 입력해요. (입력할 때 화면에 안 보이는 게 정상이에요)
- `mysql>` 이 보이면 들어온 거예요.

### 2-2. 테이블 개수 보기
`mysql>` 에서 한 줄씩 입력해요. (`goodsbridge` 는 `.env`의 `DB_NAME` 값. 안 바꿨으면 그대로)
```sql
USE goodsbridge;
SELECT COUNT(*) AS 테이블수 FROM information_schema.TABLES WHERE TABLE_SCHEMA = DATABASE();
```

| 결과 | 뜻 | 할 일 |
|---|---|---|
| `0` | 테이블이 하나도 없음 (서버를 아직 안 켠 새 DB) | **서버를 켜면 돼요** (1-③) |
| `27` 처럼 숫자 | 테이블이 이미 있음 | 아래 2-3 으로 |

테이블 이름까지 보고 싶으면:
```sql
SHOW TABLES;
```

### 2-3. 알림 테이블이 오래된 것인지 확인 (이미 테이블이 있는 사람만)
```sql
SELECT COLUMN_NAME, COLUMN_TYPE FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'notifications_tb' AND COLUMN_NAME IN ('type','reference_type');
```

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 아무것도 안 나옴 (`Empty set`) | 알림 테이블이 아직 없음 | 아무것도 안 해도 돼요 (서버를 켜면 새로 만들어져요) |
| `COLUMN_TYPE` 에 **`PAYMENT_COMPLETED`** 가 들어 있음 | 이미 최신 | 아무것도 안 해도 돼요 |
| `varchar(40)` | 이미 수정됨 | 아무것도 안 해도 돼요 |
| `enum('AUCTION_BID','AUCTION_WIN','EXCHANGE_APPROVED','EXCHANGE_REJECTED','EXCHANGE_REQUEST')` 처럼 **5개뿐** | 예전 칸 → 새 알림이 저장 안 됨 | **아래 2-4 를 실행** |

### 2-4. (예전 칸인 사람만) 알림 칸 고치기
`mysql>` 에서 아래를 **통째로** 붙여 넣어요. 여러 번 실행해도 안전하고, 기존 알림은 그대로 남아요.
```sql
SET @enum_cols = (SELECT COUNT(*) FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'notifications_tb' AND COLUMN_NAME IN ('type','reference_type') AND DATA_TYPE = 'enum');
SET @table_exists = (SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'notifications_tb');
SET @sql = CASE WHEN @table_exists = 0 THEN 'SELECT ''테이블이 아직 없어요. 서버를 한 번 켠 뒤 다시 실행하세요'' AS info' WHEN @enum_cols = 0 THEN 'SELECT ''이미 바뀌어 있어요'' AS info' ELSE 'ALTER TABLE notifications_tb MODIFY type VARCHAR(40) NOT NULL, MODIFY reference_type VARCHAR(40) NULL' END;
PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt;
```
같은 내용이 `docs/sql/fix_notifications_columns.sql` 에도 있어요. 자세한 설명은 [알림 DB 컬럼 수정 안내](알림_DB_컬럼_수정_안내.md).

### 2-5. 나오기
```sql
exit
```

## 3. 자주 막히는 경우
| 증상 | 원인 | 해결 |
|---|---|---|
| `docker` 를 인식할 수 없음 | Docker Desktop 미설치/미실행, 또는 터미널이 설치 전에 열려 있었음 | Docker Desktop 설치·실행 후 PowerShell을 **다시 열기** |
| `docker compose up -d` 가 `port is already allocated` | 내 컴퓨터에 이미 MySQL 이 3306 포트를 쓰는 중 | `.env` 에 `DB_PORT=3310` 처럼 다른 번호를 적고 `docker compose up -d` 다시 |
| `docker ps` 에 `goodsbridge-mysql` 이 안 보임 | 컨테이너가 꺼짐 | Docker Desktop 실행 확인 후 `docker compose up -d` |
| 서버가 DB 연결 오류로 안 켜짐 | DB 컨테이너가 아직 안 떴거나 `.env` 의 DB 값이 다름 | `docker ps` 로 확인, `.env` 의 `DB_PASSWORD`/`DB_NAME` 확인 |
| 비밀번호를 바꿨는데 접속이 안 됨 | DB 는 **처음 만들 때** 비밀번호가 정해져서, 나중에 `.env` 를 바꿔도 기존 DB 에는 반영 안 됨 | 데이터가 지워져도 되면 `docker compose down -v` 후 `docker compose up -d` |

> `docker compose down -v` 는 **DB 데이터를 모두 지워요.** 데모 데이터는 서버를 켜면 다시 만들어지지만, 직접 만든 데이터는 사라져요.

## 4. 데모 모드 / 데모 데이터
`.env` 에 `APP_DEMO_ENABLED=true` 를 적고 서버를 켜면 로그인·결제 없이 바로 써 볼 수 있어요.
자세한 방법과 주의할 점은 [데모 임시데이터 사용법](데모_임시데이터_사용법.md) 을 보세요.
